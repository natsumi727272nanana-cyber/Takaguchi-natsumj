# 美容室 月次KPIレポート（本店・茶屋町店）

SALON BOARD と Airペイ の CSV を月1回取り込み、**店舗別・スタイリスト別のKPI表（Excel）** を作る道具です。
顧客の氏名・電話番号などは読み込んだ直後に捨て、ファイルにもレポートにも残しません。

---

## 1. 毎月の作業（所要 10〜15分の想定）

1. SALON BOARD と Airペイ から前月分のCSVをダウンロード
2. 次のフォルダに置く（ファイル名は `salonboard` / `airpay` で始まれば何でもよい）
   ```
   data/
     raw/
       2026-09/
         honten/      salonboard.csv  airpay.csv
         chayamachi/  salonboard.csv  airpay.csv
     manual/
       monthly_costs.csv   ← 人件費・HPB掲載費を手入力
   ```
3. `monthly_costs.csv` に1店舗1行を追記
   ```
   month,store,labor_cost,hpb_cost
   2026-09,honten,3600000,450000
   2026-09,chayamachi,3300000,380000
   ```
   人件費は「給与＋社会保険の会社負担＋業務委託費」を推奨（どこまで含めるかを一度決めて毎月同じにする）。
4. 実行
   ```
   python -m salon_kpi build --month 2026-09
   ```
   → `output/kpi_2026-09.xlsx` ができます。

**初回だけ** `python -m salon_kpi inspect` を実行し、実CSVの列名が正しく対応したか確認してください。
列名の候補（`config.toml`）は実ファイルを見ずに作った**推測**です。合わない列は `config.toml` に追記します。

必要なもの: Python 3.11以上、`pip install pandas openpyxl`

## 2. レポートの中身

| シート | 誰が見る | 内容 |
|---|---|---|
| 幹部サマリー | 経営者・幹部 | 6項目 × 店舗 ×（当月・前月・前年同月）＋目標まで |
| スタイリスト別 | 店長 | 売上・客数・新規・客単価・指名率・スパ付帯率・来店周期・新規再来率 |
| 店舗別推移 | 経営者 | 全期間の月次推移（前月比・前年同月比つき） |
| 売上突合 | 経理 | SALON BOARD売上 と Airペイ決済額の差 |
| データチェック | 作成者 | 列の対応状況、読み捨てた列名、警告 |

## 3. 幹部サマリーの6項目（5〜6に絞った理由）

候補7項目のうち、幹部が**自分で打ち手を決められる**ものを残しました。

| # | 項目 | なぜ入れるか | 幹部の打ち手 |
|---|---|---|---|
| 1 | 売上（目標まで） | 結果指標。目標1,000万との差を毎月見る | — |
| 2 | 新規客数 | HPB投資の成果そのもの | 掲載プラン・クーポン |
| 3 | 新規再来率（90日） | 新規を「店の客」にできているか。HPB費の回収可否を決める | 初回カウンセリング、次回予約の提案 |
| 4 | 客単価 | 売上＝客数×客単価のもう一方 | メニュー構成、スパ提案 |
| 5 | 指名率 | スタイリストの固定客化 | 育成、担当割り |
| 6 | 人件費率（店舗のみ） | 売上が伸びても利益が残るかの防波堤 | シフト・採用ペース |

**外したもの**
- **スパ付帯率** → 客単価を上げる「手段」の一つなので、幹部サマリーでは客単価で見て、スタイリスト別シートで原因を探す位置づけにしました。ヘッドスパを店の柱として打ち出す方針なら `config.toml` の `executive_kpis` で指名率と入れ替えてください。
- **既存（再来）客数** → 売上・新規客数から逆算でき、行動に直結しにくい。推移シートには残しています。

### 各案の評価

| 観点 | 評価 |
|---|---|
| 顧客への影響 | 直接はなし。ただし新規再来率を追うと「初回の体験」の改善に目が向くので、顧客にはプラス |
| 収益性 | 新規1人あたりHPB費（推移シート）と新規再来率を並べると、HPB費が回収できているか判断できる |
| スタッフ負荷 | 入力作業は月1回・作成者1人のみ。**スタイリスト別の数字を全員に貼り出すかは慎重に**（下記） |

## 4. KPI定義

| 項目 | 定義 |
|---|---|
| 売上 | SALON BOARDの会計金額合計（税込/税抜は `config.toml` の `sales_tax` で明記） |
| 客数 | 来店数（伝票番号列があれば伝票単位、なければ1行＝1来店） |
| 新規客数 | 来店区分が「新規」の来店数。区分列が無い場合は「その店で初めて見たお客様番号」 |
| 客単価 | 売上 ÷ 客数 |
| 新規再来率 | ある月の新規客のうち、初回から90日以内に**同じ店**に再来した割合。90日経過していない月は空欄（未確定） |
| 指名率 | 指名ありの来店 ÷ 客数 |
| スパ付帯率 | メニュー名に「スパ」を含む来店 ÷ 客数 |
| 来店周期 | その月に再来したお客様が、同じ店の前回来店から何日空けて来たかの中央値。担当はその月の担当者 |
| 人件費率 | 手入力の人件費 ÷ 売上（店舗単位のみ） |
| 新規1人あたりHPB費 | 手入力のHPB掲載費 ÷ 新規客数 |

スタイリスト別の売上・新規再来率は、**メイン担当（伝票の先頭行の担当者／新規時の担当者）に計上**します。アシスタントの貢献は数字に出ません。

## 5. 率直な注意点

### 事実
- 茶屋町店は2026/8開店で、まだ2か月分しかデータがありません。月700万は開店直後の数字です。
- 新規再来率は90日待たないと確定しません。今月の判断に使えるのは「3か月前に来た新規」の結果です。

### 推測（データで確認が必要）
- **本店の売上低下の原因**：「新店開店で下がった」と見るなら、開店前（2025/8〜2026/7）の本店CSVも取り込んで、**前年同月比**で比べる必要があります。前月比だけだと季節変動と区別できません。最低でも2025/8以降、できれば2024/8以降を一度に取り込むことを勧めます。
- **本店客の茶屋町への移動**：SALON BOARDが店舗ごとに別アカウントの場合、お客様番号は店舗間で一致しないはずです。その場合、本店から茶屋町へ移ったお客様は「本店では離反・茶屋町では新規」に見え、茶屋町の新規数と本店の離反を両方とも**過大に**見せます。実際の運用を確認してください。
- **Airペイとの差額**：現金払い・回数券・物販の扱いでずれるのが普通です。差額が毎月ほぼ一定なら問題なし、急に変わった月は会計漏れを疑う、という使い方を想定しています。

### 感情面の配慮（スタッフ）
- スタイリスト別の数字を全員に順位表で見せると、新卒・若手が萎縮したり、指名客の取り合いが起きることがあります。**店長と本人の1on1で本人の数字だけ見せる**運用から始めるのが無難です。
- 来年の新卒4名は、入社後しばらく売上・指名率が低く出ます。「育成中」のスタッフは別枠で見る前提を幹部と共有しておいてください。

### 1,000万目標について
本店 約800万→1,000万は+25%、茶屋町 約700万→1,000万は+43%です。客単価を据え置くなら客数で同じ比率の増加が必要で、それに見合う席数・スタイリスト稼働があるか（＝人件費率がどう動くか）を、出店判断の前にこの表で確認することを勧めます。

## 6. 個人情報の扱い

- 設定した列（日付・担当・お客様番号・来店区分・指名・金額・メニュー・伝票番号）以外は読み込み直後に破棄
- お客様番号はソルト付きハッシュに変換してメモリ上でのみ使用。ソルトは `.salt`（Git管理外）
- メニュー名はスパ判定にだけ使い、出力しない
- `data/`・`output/`・`.salt` は `.gitignore` 済み。**実CSVをGitにコミットしないこと**
